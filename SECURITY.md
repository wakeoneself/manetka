# Модель безопасности

## Границы доверия

Renderer отображает локальную React-сборку. Node integration выключена, sandbox и context isolation включены. Доступ к основному процессу — только через перечисленные операции preload. IPC проверяет главное окно и основной frame, адрес документа, размер и схему параметров. Произвольного shell/FS API в renderer нет. Секреты раскрываются только по явному действию пользователя. Профили внутри одного хранилища не являются отдельными границами шифрования.

Production-контент обслуживается через собственный безопасный протокол `manetka://app/` с ограничением путей. CSP запрещает сторонние скрипты, iframe, плагины и формы. Навигация, новые окна, webview и разрешения браузера заблокированы. Renderer не обращается к внешним сайтам. Main использует SSH, DNS и загрузки только в рамках запрошенной настройки. Нет аналитики, телеметрии, аккаунтов или автообновления.

В упакованном приложении Electron fuses отключают RunAsNode, NODE_OPTIONS и CLI inspector, включают ASAR integrity и загрузку только из ASAR. Локальная ad-hoc подпись требует временного entitlement disable-library-validation; публичный выпуск должен иметь Developer ID, нотарификацию и отдельную проверку entitlements. Dev-среда и браузерный preview не эквивалентны защищённой сборке.

## Хранилище

AES-256-GCM, случайный nonce 96 бит при каждой записи, salt 256 бит, scrypt N=32768/r=8/p=1, 256-битный ключ, фиксированный AAD с идентификатором формата и KDF. Параметры KDF не принимаются произвольно из файла. Повреждение ciphertext, nonce или тега приводит к отказу расшифрования. Пароль минимум 12 символов; предпочтительна длинная уникальная фраза.

Запись рабочего файла: временный файл с O_EXCL/0600, flush и atomic rename. Создание и сохранение копии запрещают перезапись существующего файла: публикация через hard link, на ФС без hard link — COPYFILE_EXCL. Последний вариант не гарантирует атомарности копирования. Служебные каталоги создаются с mode 0700; права выбранной пользователем существующей папки не меняются. Сохраняется весь объект, включая имена серверов и IP. На Windows POSIX mode не является полноценным ACL и требует отдельной проверки. Ключ derivation хранится в main и обнуляется при блокировке. JavaScript-строки и копии в памяти невозможно гарантированно обнулить: дампы процесса, swap, захват экрана, вредоносный процесс и полный доступ к учётной записи вне модели защиты. Пароль не хранится в localStorage, keychain или исходниках.

Хранилище — выбранный пользователем файл .manetka. Список прежних хранилищ импортируется из каталога `monetka` только при отсутствии нового списка в `manetka`; пути остаются прежними. Файлы `.monetka` и `monetka.vault` поддерживаются без перемещения и перезаписи. Для старого аутентифицированного заголовка используется прежний AAD; новые записи шифруются с заголовком и AAD `manetka`. Подмена одного заголовка без повторного шифрования не проходит проверку GCM. В `userData/vaults.json` находятся пути, ID и даты недавних файлов; имена и расположение файлов не шифруются. Содержимое разных хранилищ шифруется независимо. Переключение блокирует предыдущий файл и запрещено на время операции с VPS. Автоблокировка по бездействию и системным событиям. На время операции с VPS блокировка main откладывается, чтобы не оборвать изменение посередине; окно при ручной блокировке скрывает содержимое сразу. При закрытии последнего окна macOS хранилище блокируется.

## SSH и провиженинг

Журнал провиженинга не является интерактивной shell-консолью. Для команд установки main распознаёт только допустимые сообщения APT/curl/Go/make и передаёт нормализованные поля. Произвольные stdout/stderr, исходный скрипт и содержимое передаваемых файлов остаются в main; у остальных команд трансляция вывода отключена. Строки ограничены 4096 символами, частота и история ограничены. События находятся только в памяти, очищаются при блокировке и не входят в audit или резервную копию. Heartbeat означает ожидание команды, а не подтверждение её полезной работы. Процент показывается только в сообщениях curl, когда он известен самому curl.

SSH-ключи находятся в общем реестре хранилища. Серверы ссылаются на ID; приватная часть разрешается только в main перед соединением. Public state содержит публичную часть, fingerprint, алгоритм, дату и ссылки на серверы, без приватных материалов и паролей. Новые пары — Ed25519. Необязательный пароль использует OpenSSH bcrypt KDF (32 rounds) и AES-256-CTR внутри формата ключа. Пароль сохраняется в том же зашифрованном хранилище и не является независимым фактором защиты открытого приложения.

Операция удаления проверяет связи во всех профилях независимо от состояния сервера. Учитываются незавершённые установки: ключ и pending-ссылка сохраняются до установки на VPS; повторная попытка использует тот же ключ. Проверка выполняется внутри сериализованной операции main. Корректные старые inline-ключи мигрируют с дедупликацией по fingerprint; некорректный старый ввод сохраняется для ручного исправления. Соответствие публичной и приватной частей проверяется при открытии/импорте. Защита удаления относится ко всем профилям выбранного файла. Другие зашифрованные хранилища независимы и без их паролей не анализируются.

Публичный ключ копируется через узкую main-операцию по ID; приватная часть через IPC не передаётся. Экспорт приватного ключа выполняется через native-диалог с отдельным предупреждением, с mode 0600 в том числе для существующего файла. Без дополнительного пароля экспортированный приватный файл не зашифрован.

Сначала получается fingerprint без успешной аутентификации. При первом доверии пользователь обязан сверить его с независимым источником. Подтверждение по принципу TOFU без независимой сверки не защищает от MITM при первом соединении. Дальнейшие подключения требуют точного совпадения закреплённого ключа. Смена ключа блокируется.

Пароли и приватные ключи идут по SSH, не через shell argv. Команды выполняются как фиксированный `bash -se`, скрипт передаётся в stdin. Пользовательские параметры валидируются; динамические shell-значения цитируются. Файлы передаются по SFTP и заменяются OpenSSH posix-rename. Нужны root и OpenSSH на выделенном VPS поддерживаемой ОС.

При усилении безопасности парольный вход переводится на отдельный сгенерированный Ed25519-ключ maNETka. Новый вход проверяется до замены сохранённого credential и отключения паролей. При исходном входе собственным ключом используется он. Существующие authorized_keys не перезаписываются. При очистке удаляется только строка с marker этой записи maNETka.

Новые ресурсы привязаны к `/etc/manetka/owner`. У старых записей без `resourceNamespace` сохраняется `/etc/monetka/owner` и прежние имена служб, SSH-маркеров и каталогов. Namespace выбирается из закрытого набора, не из пользовательского ввода. Проверка владельца блокирует наличие стека другой версии имени на том же VPS. Чужая запись владельца блокирует операцию. Ключи и намерение записываются локально до изменения VPS. При сбое остаётся состояние «Нужна проверка» с возможностью повторно применить сохранённые материалы. Это журналируемая операция, а не полноценная транзакция или безусловный rollback всей ОС.

Xray/Caddy скачиваются по закреплённым URL с проверкой SHA-256. AmneziaWG собирается из закреплённых исходников; Go toolchain также закреплён по SHA-256, зависимости проверяет Go module checksum. apt использует подписанные репозитории ОС. Поставщики релизов, репозитории ОС и исходные проекты остаются доверенными сторонами; hash не защищает от компрометации upstream до фиксации.

Firewall использует собственные MN_* chains для IPv4/IPv6, открывает SSH на указанном порту и VPN, остальное входящее/транзит закрывает. Чужие цепочки не очищаются. Изменённый firewall имеет таймер отката 120 секунд: отменяется только после второго SSH-подключения. Откат не покрывает сторонние изменения, переустановку ОС и отказ самой сети провайдера. Сохраняйте консольный доступ. В bridge-режиме разрешены только выбранные TCP/UDP-направления; endpoint VPN защищает содержимое, но L4 relay не скрывает метаданные соединения.

## Файлы и копии хранилищ

«Сохранить копию» создаёт полноценный .manetka с тем же паролем. При открытом хранилище снимок текущего состояния шифруется с новым nonce; при заблокированном копируется существующий зашифрованный файл. Копия открывается отдельно и не заменяет другое хранилище. ZIP-код и библиотека fflate удалены. Старые ZIP новым интерфейсом не поддерживаются; для переноса из старой версии нужен её файл monetka.vault.

Создание нового файла после забытого пароля не меняет старый файл. Для расшифровки нужен пароль именно этого файла, recovery/backdoor нет. Удаление из недавних путей затрагивает только каталог. Файлы ограничены 32 МиБ; схема и ссылки проверяются после аутентифицированного расшифрования. Внешняя замена или удаление рабочего файла обнаруживается по SHA-256 зашифрованных байтов перед сохранением; это защита от обычных конфликтов, а не распределённая блокировка. Синхронизация и слияние одновременно изменяемых копий не реализованы. Старые копии могут содержать отозванные доступы: открытие копии не откатывает VPS и не защищает от rollback пользовательского состояния.

Экспортированные .conf/.txt, QR и буфер обмена содержат секреты. Файлу задаётся mode 0600 при создании, но приложение не управляет другими копиями, внешними дисками и мессенджерами. QR/текст скрываются через минуту или при блокировке. Буфер обмена автоматически не очищается: после использования удалите скопированный ключ.

## Очистка

Требует повторения IP и удаления связанных маршрутов. Удаляются службы maNETka, её конфиги/ключи, бинарники в собственном каталоге, служебные пользователи, собственные iptables chains и SSH drop-in. ОС, установленные apt-пакеты, чужие файлы, системный журнал, snapshots, swap и SSD wear-leveling остаются. Физическое уничтожение VPS не заявляется. Нужна переустановка/удаление ресурса через провайдера.

## Что ещё проверить перед выпуском

Полные реальные установки, handshake и утечки DNS/IPv6 на каждой ОС/архитектуре; корректность AmneziaWG с выбранными клиентами; перезагрузку и отказ по шагам; изменения firewall под нагрузкой; открытие старых файлов и конфликты владельца; Windows ACL; Developer ID/нотарификацию; обновление зависимостей; независимый аудит IPC, криптографии и SSH-адаптеров. Наличие этих ограничений не следует скрывать в релизном описании.
