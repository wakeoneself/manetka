# maNETka

Локальное Electron-приложение для управления личными VPN-серверами и отдельными конфигами. macOS — первая целевая платформа. Без аккаунтов, подписок и серверной базы пользователей.

Название в интерфейсе и сборках: **maNETka**. Технические имена, IPC, протокол приложения и новые файлы используют `manetka`; расширение хранилищ — `.manetka`. Логотип — векторная N-маршрут внутри монеты; исходник: `src/assets/logo.svg`.

## Запуск из исходников

Требуется Node.js 22.12+ и npm. Из каталога проекта:

```sh
npm ci
npm run build
npm start
```

Разработка: `npm run dev`. Предпросмотр интерфейса без SSH: `npm run dev:web`, затем откройте адрес Vite и выберите «Посмотреть демо». Демонстрационные IP взяты из зарезервированных диапазонов и не используются для соединений.

Локальная macOS-сборка: `npm run pack`. Установочные архивы: `npm run dist:mac`. В конфигурации включена ad-hoc подпись для локальной разработки; Developer ID и нотарификация для публичного распространения ещё не настроены. Для выпуска замените настройки подписи и entitlements после проверки. `npm run dist:win` и `npm run dist:linux` подготовлены, но сборки и поведение на Windows и Linux не проверены.

## Выпуск релиза

Релизы собирает GitHub Actions (`.github/workflows/release.yml`) по тегу `v*`:

1. Обновите `version` в `package.json` и добавьте раздел `# X.Y.Z` в `CHANGELOG.md` — он станет описанием релиза.
2. Закоммитьте, затем `git tag vX.Y.Z && git push origin master vX.Y.Z`.

Workflow проверяет, что тег совпадает с версией, прогоняет тесты, собирает macOS arm64 и x64 и публикует `.dmg` и `.zip` в GitHub Release.

## Реализовано

- Серверы: IPv4, root, произвольный SSH-порт, пароль или приватный ключ с passphrase. Проверка SSH fingerprint до аутентификации; закрепление ключа и блокировка при его смене.
- Провиженинг выделенных Ubuntu 22.04/24.04, Debian 12/13 с systemd, x86_64 или ARM64.
- WireGuard; AmneziaWG с базовым совместимым набором параметров AWG 1.x; VLESS + REALITY/Vision; VLESS + XHTTP/REALITY; VLESS + WebSocket/TLS через Caddy.
- Отдельные ключи/UUID для устройств, выбор протокола по возможностям сервера, DNS/MTU/AllowedIPs для WG/AWG, экспорт файла, QR и отзыв на сервере.
- TCP/UDP-мосты с DNAT/SNAT для WG/AWG/REALITY/XHTTP. Созданный маршрут доступен в мастере конфига.
- Независимые зашифрованные файлы .manetka со своими паролями, выбор недавних хранилищ и места сохранения, профили, автоблокировка, блокировка при сне/блокировке macOS. Во время изменения VPS автоблокировка откладывается до окончания операции.
- «Сохранить копию» создаёт самостоятельный .manetka со всеми данными и тем же паролем. Для восстановления откройте копию как обычное хранилище. ZIP не используется.
- Очистка установленных maNETka служб, ключей, файлов и собственных правил firewall, с подтверждением по IP.
- Спокойный минималистичный интерфейс, тёмная и светлая темы, инструкции, журнал без секретов.
- Живой ход провиженинга: этапы, таймер, нормализованный вывод установки пакетов/загрузок/сборки, heartbeat тихих команд и журнал с управляемой автопрокруткой. После завершения результат остаётся открытым. При восстановлении настройки журнал доступен через кнопку «Журнал».

## Порядок работы

В разделе «SSH-ключи» хранится общий список для всех профилей. Можно сгенерировать Ed25519 заранее или прямо при добавлении VPS, выбрать сохранённый ключ, скопировать публичную часть и экспортировать файл. Корректные SSH-ключи из старых хранилищ и резервных копий автоматически переносятся в список.

До проверки доступа с новым ключом добавьте его публичную часть через панель провайдера или в `/root/.ssh/authorized_keys`. При настройке сервера по паролю с усилением безопасности maNETka создаёт и устанавливает ключ автоматически. Приватная часть и необязательный пароль ключа хранятся внутри зашифрованного хранилища и включаются в резервную копию.

Удаление запрещено, пока ключ связан с сервером в любом профиле, включая недоступные серверы и прерванные установки. Проверка выполняется в основном процессе. После штатного удаления связанных серверов ключ становится свободным. Использование ключа вне своего хранилища приложение определить не может.

1. Откройте файл .manetka или создайте новый, задайте длинный уникальный пароль и выберите место сохранения. Если пароль забыт, можно создать другое хранилище; старый файл останется на диске. Сброса пароля и расшифровки без него нет.
2. Добавьте выделенный VPS. Сверьте fingerprint через доверенную консоль провайдера. В консоли Linux: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`. Убедитесь, что сверяете ключ того же алгоритма, который использует SSH-соединение.
3. Проверьте SSH-доступ и систему. Выберите сервер и добавьте VPN-протокол. Прочитайте план: firewall закроет прочие входящие порты, поэтому VPS должен быть выделен для VPN. Сохраните доступ к консоли провайдера.
4. Создайте конфиг устройства. Для WG/AWG используйте соответствующий клиент; для VLESS — совместимый Xray-клиент. Сохранённый конфиг содержит незашифрованный приватный ключ.
5. Проверьте реальное соединение, внешний IP, DNS и отсутствие обхода через IPv6. Запущенная systemd-служба сама по себе не доказывает работоспособность клиентского туннеля.
6. Выберите «Хранилище» → «Сохранить копию». Сохраните .manetka отдельно от рабочего файла; пароль у копии тот же.

Для моста сначала нужны два проверенных сервера и VPN на выходном. После создания моста выберите его в поле «Подключение» при создании конфига. Это пересылка порта: шифрование обеспечивает VPN между клиентом и выходом, отдельный шифрованный канал между VPS не создаётся.

## Файлы хранилищ

Вся база находится в одном зашифрованном .manetka: профили, серверы, SSH-ключи, VPN-конфиги, маршруты и настройки. Файлы независимы и переносятся на другой компьютер. Это собственный формат maNETka; совместимость с KDBX не заявляется. При первом запуске список недавних файлов переносится из прежнего каталога `Application Support/monetka` в `Application Support/manetka`. Старые `.monetka` и `monetka.vault` открываются с прежним паролем и остаются на своих местах. После сохранения открытого файла или его копии используется новый заголовок `manetka-vault`; содержимое зашифровано как прежде. Новые файлы по умолчанию предлагаются в `Application Support/manetka/vaults`, место можно выбрать в системном диалоге. Точный путь виден на экране входа и в настройках, рядом есть действие «Показать в папке».

Недавние пути записываются отдельно в `vaults.json`, без паролей и содержимого базы. «Убрать из списка» не удаляет файл. Если файл был перемещён, откройте его по новому пути. При внешнем изменении открытого файла сохранение блокируется, чтобы не затереть другую версию; автоматического слияния и синхронизации нет.

## Ограничения и проверка

Это первая рабочая версия, а не прошедший независимый аудит продукт. Автоматические локальные проверки не заменяют испытания на выделенном VPS.

- Полный путь установки каждого протокола, клиентский handshake, NAT, перезагрузка, отзыв и очистка требуют проверки на тестовых VPS обеих архитектур.
- SOCKS-hop, reverse proxy и автоматическое управление Cloudflare пока не поддерживаются. WebSocket/CDN требует своего домена и ручной настройки DNS/CDN. L4-мост для WebSocket/TLS не поддерживается.
- Интернет через IPv4. В стандартном полном WG/AWG-туннеле `::/0` направляется в туннель, IPv6-транзит блокируется. Изменение AllowedIPs может разрешить обход VPN.
- maNETka не подключает сам Mac к VPN: она управляет VPS и выпускает конфиги для отдельных клиентов.
- Очистка не стирает физический диск, чужие данные или снимки провайдера. Пакеты из apt остаются. Полный сброс VPS выполняется у хостера.
- Профили разделяют списки внутри одного хранилища и одного пароля. Это не изоляция от другого пользователя, который знает пароль.
- Восстановление старой копии не откатывает VPS и может содержать старые ключи. Не применяйте старое состояние без проверки: повторная настройка может вернуть ранее отозванные доступы.

## Проверки

```sh
npm test
npm run build
npm run test:ui
node scripts/check-ssh-keys-ui.mjs
npm run test:progress-ui
npm run test:vaults-ui
npm run test:electron
```

`test:ui` запускает локальный Brave Browser и сохраняет снимки. `test:electron` использует временное хранилище и зарезервированный IP: SSH-соединение не выполняется. SSH-тесты поднимают временный сервер только на loopback.
